What one run does

一次 run 做了什麼

一次 run 做了什么

  1. Copy the task's starting files into a fresh workspace and create a fresh, empty HOME with only that CLI's login.
  2. Start a local recording proxy. Every model request goes through it; it logs usage, model, effort, request size and time to first token, never headers or bodies.
  3. Run the CLI with the same prompt and the same model as every other cell. Web search and fetch are turned off for every CLI.
  4. Grade automatically: run the tests, compile the Lean proof, check the report's key lines, or run the lab's own check script.
  5. Append the raw record. Records are never overwritten; a run that hit an infrastructure fault moves to _infra-failed/ and does not count.
  1. 把任務的初始檔案複製到全新工作區，建立一個全新、空白的 HOME，只放這個 CLI 的登入資訊。
  2. 啟動本機記錄代理。所有模型請求都經過它，記下用量、模型、effort、請求大小、首 token 時間，不記請求標頭和內容。
  3. 用和其他格相同的提示與模型執行 CLI。所有 CLI 都關閉網頁搜尋與抓取。
  4. 自動評分：跑測試、編譯 Lean 證明、核對報告關鍵行，或執行排障環境自己的驗收腳本。
  5. 追加原始紀錄，從不覆蓋；遇到環境故障的 run 移到 _infra-failed/，不計入結果。
  1. 把任务的初始文件拷贝到全新工作区，创建一个全新、空白的 HOME，只放这个 CLI 的登录信息。
  2. 启动本地记录代理。所有模型请求都经过它，记下用量、模型、effort、请求大小、首 token 延迟，不记请求标头和内容。
  3. 用和其他格相同的提示与模型运行 CLI。所有 CLI 都关闭网页搜索与抓取。
  4. 自动评分：跑测试、编译 Lean 证明、核对报告关键行，或运行排障环境自己的验收脚本。
  5. 追加原始记录，从不覆盖；遇到环境故障的 run 移到 _infra-failed/，不计入结果。

Rounds are interleaved: round r runs every (task, CLI) pair once, in an order shuffled by seed, so no CLI is always first (cold cache) or always last. The harness refuses to run fewer than 3 repetitions.

各輪交錯執行：第 r 輪把每個（任務, CLI）各跑一次，順序按種子打亂，沒有 CLI 永遠第一個（冷快取）或永遠最後。少於 3 次時套件直接拒絕執行。

各轮交错运行：第 r 轮把每个（任务, CLI）各跑一次，顺序按种子打乱，没有 CLI 永远第一个（冷缓存）或永远最后。少于 3 次时套件直接拒绝运行。

Public benchmarks, perturbed

公開基準題，加上擾動

公开基准题，加上扰动

Our own tasks are too easy to separate CLIs by success rate, so we also run 20 hard tasks from public suites: Terminal-Bench 2.0 (8), SWE-bench Pro (8) and SpreadsheetBench Verified (4). To keep models from recalling published answers, every task has a seeded variant: reworded instructions, renamed files, paths, ports and output formats, regenerated inputs and answers, with the graders updated to match. A variant is used only after the reference solution passes it; all 20 do. SWE-bench Pro runs with the git history stripped so the upstream fix cannot be read back.

自家任務太容易，各 CLI 幾乎都 100% 通過，分不出完成率，所以另外跑 20 題公開基準難題：Terminal-Bench 2.0 8 題、SWE-bench Pro 8 題、SpreadsheetBench Verified 4 題。為了避免模型背出公開答案，每題都有帶種子的擾動版本：改寫指示，改檔名、路徑、連接埠與輸出格式，重新產生輸入與答案並同步更新評分腳本。參考解通過後才使用，20 題全部通過。SWE-bench Pro 執行時會移除 git 歷史，讀不到上游修復。

Why dsh and opencode lead on Claude

為什麼 dsh 和 opencode 在 Claude 側領先

为什么 dsh 和 opencode 在 Claude 侧领先

  • The gap is almost all SWE-bench Pro. On TB2, dsh, opencode and official score 58%, 58% and 56%; on SWE-bench Pro 77%, 73% and 58%. On the 5 Pro tasks that separate cells, dsh passes 25/30, opencode 23/30, official 16/30, this fork 13/30.
  • They work longer, not with better tools. On those 5 tasks a dsh run averages 15.2 tool calls, 16.3k output tokens and 2.9 test runs; official averages 9.4, 9.9k and 1.9. Time and cost go up about 50%. Over 90% of calls in every CLI are bash; edit tools, LSP feedback, subagents, todo lists and compaction were barely used or never triggered.
  • dsh vs pi is the clean comparison: same model library, both send effort low, and dsh still leads by 18 points. Its system prompt is one line plus one rule per tool, such as "check the [exit code: N] marker on every bash result; investigate failures before moving on".
